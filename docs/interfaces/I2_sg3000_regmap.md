代码里的唯一定义：`include/sg3000_regs.h`。本文档解释它，两者不一致时以头文件为准并修正本文档。

## 1. 地址空间

| 空间 | 大小 | 谁访问 | 内容 |
|---|---|---|---|
| BAR0 | 16 MiB | 用户态，经驱动白名单 | 邮箱、块头、采集控制；[逆向] 串口邮箱 0x4110xx/0x4130xx、UART16550 0x1000/0x11000（见 I7）|
| BAR1 | 64 KiB | 只有内核驱动 | XDMA 引擎（C2H 0x1000，IRQ 块 0x2000，配置块 0x3000，SGDMA 描述符 0x5000）|
| 逻辑地址 | — | 经 BAR0 邮箱，由卡固件代访问 | DDR 状态、Camera Link 状态、启停 |

## 2. 驱动白名单（`board/driver/sg3000_rx.c` 第 92-100 行）

| 方向 | 地址 | 额外限制 |
|---|---|---|
| 写 | 0x412010 邮箱发送数据 | — |
| 写 | 0x412014 邮箱发送长度 | 值只能是 28 或 32 |
| 写 | 0x202000 块头确认 | 值只能是 0xFFFFFFFF |
| 写 | 0x201000 采集预备 | 值只能是 2 |
| 读 | 0x41200c、0x41201c、0x412020、0x412024 | 邮箱状态与回复 |
| 读 | 0x202008 – 0x20206c、0x202098、0x20209c | 块头与状态 |

白名单是安全网：GPT 猜的地址即使写错，也只能写这四个地址、这几个值。**放宽白名单前必须有厂家依据。**

## 3. 邮箱报文

BAR0 上有三套同构邮箱 [逆向]：

| 基址 | 用途 | 第 1 字 |
|---|---|---|
| 0x411000 | Camera Link 串口 0 | 0x10 |
| 0x412000 | 卡固件（本节）| 0 |
| 0x413000 | Camera Link 串口 1 | 0x12 |

串口两套的细节见 I7。下面只讲卡固件邮箱。

请求（每格 32 位，小端）：

| 字 | 读请求 | 写请求 |
|---|---|---|
| 0 | 0x000155aa | 0x000155aa |
| 1 | 0 | 0 |
| 2 | 12 \| 请求号<<16 | 16 \| 请求号<<16 |
| 3 | 0 | 0 |
| 4 | 0x80000000 | 0x80020000 |
| 5 | 逻辑地址 | 逻辑地址 |
| 6 | 4 | 4 |
| 7 | — | 1（写入值）|

回复检查：长度（读 32 / 写 28 字节）、魔数 0x000055aa、偏移 4 = 1、偏移 8 = 16/12、偏移 18 = 0x8001/0x8003、偏移 24 = 4/0。
偏移 10 是 ACK 计数：**和请求号无关**，但同一会话内必须逐条 +1。读回复的值在偏移 28。

## 5. 卡的 GenICam 参数名（2026-11-07，来自 VisionKit 示例源码）

Windows 软件连接后会设置的卡参数见 `docs/vendor/README.md`。其中三个和我们预检读的逻辑地址**顺序、含义都对得上**：

| 示例源码里的参数 | 我们读的逻辑地址 | 实测 | 推测 |
|---|---|---|---|
| `ClConfiguration` | 0x10601004 | 0 | 同一个参数 |
| `CameraColorType` | 0x10601008 | 0 | 同一个参数 |
| `CameraPixelDepth` | 0x1060100c | 8 | 同一个参数 |
| `CameraScanType`、`DeviceTapGeometry`、**`CameraWidth`**、**`CameraHeight`** | 未知 | — | 可能在 0x106010xx 附近，**不要去试写** |

**[逆向] 卡的 XML 在卡存储里，Linux 能直接读出来**：
- VisionKit 的 DLL 里没有这些地址常量，全部在运行时从卡的 XML 读入。
- XML 的位置写在卡逻辑地址 **0x190** 处的 URL 字符串里（0x100 字节，第 2 路在 0x290），格式是 `Local:<文件名>;<十六进制地址>;<十六进制长度>`。
- 读取用的是和预检同一种邮箱读。

已实现：`sg_status --card-xml DIR`，也可以点中控台「02¾ 读取采集卡 XML」。**拿到它，上表就能全部确认。**
