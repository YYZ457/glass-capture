# 项目全景：哪些是黑箱，哪些还要动脑子

写给项目负责人（不需要读懂 C 代码也能用这份文档推进项目）。

## 一句话

相机拍玻璃 → 采集卡收图 → ZCU102 板子把图取进内存、找颗粒 → 结果送到电脑。
验收要回答：**30 µm 以下的颗粒，能不能找到、找得准不准**（2027 年 6–7 月）。

## 四层，从你手边往下

```
① 你操作的：电脑上的中控台（浏览器页面）          host/console/
       │ 串口发命令 / 网口收数据
② 板上的三个程序：sg3000-capture、sg3000-stream、sg_status   dist/glass-capture/
       │ 调用
③ 程序内部的模块：采集协议、处理、流水线、网口       board/
       │ ioctl
④ 驱动 sg3000_rx.ko → 采集卡 → 相机                  board/driver/（板上用的是旧编译的 .ko）
```

**日常使用只碰第 ① 层。** 每个按钮做什么、应该看到什么，见 `docs/BRINGUP.md`。

## 黑箱清单

### A. 已经做完，直接用，不用看里面

| 东西 | 怎么用 | 依据 |
|---|---|---|
| 驱动 `sg3000_rx.ko` | 中控台「从 SD 加载程序」自动加载 | 旧版已在实机上加载、采图成功 |
| 中控台的串口操作（连接、唤醒、检查板卡、日志） | 点按钮 | 原有功能，测试齐全 |
| 网口收发（`tx_tcp` ↔ `rx_tcp`） | 中控台「配置网口并测试」 | 电脑上回环测试，逐字节一致 |
| 存图（PGM 格式，不覆盖、不留半截文件） | 自动 | 测试通过 |
| SD 卡打包工具 `tools/make_sd_bundle.py` | 改了板上代码后运行一次，再拷 `dist/glass-capture` | — |
| 验证脚本 `verify/V1–V4` | 命令行跑，见 BRINGUP 第 6 节 | 合成图测过 |

### B. 设计上是黑箱，但要等第一次上板确认一下

逻辑照搬自旧代码（旧代码在实机上采到过图），电脑上用"假卡"测过；但这次重新编译的程序还没在板子上跑过。
**第一次上板，照 BRINGUP 做一遍，全部通过后就升级成 A 类。**

| 东西 | 第一次上板怎么确认 |
|---|---|
| 单帧采集 `sg3000-capture` | 「04 采集一帧」成功，图和以前旧程序采的一样 |
| 只读体检 `sg_status` | 「02½ 只读体检」输出三段，`poisoned 0` |
| 采集协议层（邮箱、块头、DMA） | 同上两步通过即确认 |
| 板子网口 | 「配置网口并测试」通过 |
| 连续采集 `sg3000-stream` | 跑 30 秒，`received` = `processed`，队列满 0 次 |
| 读采集卡 XML（`sg_status --card-xml`，新）| 「02¾ 读取采集卡 XML」存出文件，打开是 XML 或 zip |

### C. 不是黑箱：这里才是项目真正要攻关的地方

| 问题 | 现状 | 推进方式 |
|---|---|---|
| **宽度是 4096 还是 16384？** | 卡报告 4096，相机是 16K。卡的 `CameraWidth` 地址在卡自己的 XML 里，板上能读出来 | 中控台「02¾ 读取采集卡 XML」；V2：遮住左半边采一张 |
| **相机配置**（行频、曝光、触发） | 只能用出厂默认。串口通道、波特率、GenCP 已全部逆向并写成代码；只差编译新驱动（需要板子内核树）| 短期：Windows + VisionKit 配好存进相机；长期：编新 .ko → `camera-probe`（I7 第 8 节）|
| **噪声有多大、能看见多小的颗粒** | 不知道 | V3：盖镜头盖采几张 |
| **检测算法**（`sg_candidates`） | 第一版：减列背景 → 阈值 → 连通域。参数是拍脑袋的 | 用真实图在电脑上调（`host/detect/candidates.py`），再用 V4 对真值 |
| **真值**（已知大小、位置的颗粒） | 没有 | 需要标准微球样片或显微镜标定 —— 这是实验，不是代码 |
| **丢没丢行** | 只能看块号，不知道玻璃走了多远 | 将来接编码器（`sg_linecheck` 已写好记账部分） |
| **速度够不够** | 板上 CPU 处理满速 252 MB/s 能不能跟上，没测过 | 连续采集时看队列峰值；跟不上再考虑 FPGA（D001） |

## 推进路线（建议顺序）

1. **上板跑通 B 类** → 全部变成 A 类（一次实验）
2. **回答宽度问题**（V2）和**噪声水平**（V3）（一次实验，十几分钟）
3. **Windows + VisionKit 一趟**：确认相机配置、导出 16K 的 XML
4. **做真值样片**，采图
5. **电脑上调检测算法**，V4 出召回率 —— 验收数字从这里来
6. 算法定了，同步到板上 C 版本（两边输出必须一致，已有对比方法）
7. 连续采集 + 板上检测 + 网口只发候选 = 最终系统

**1–3 步是"让系统工作"，4–6 步是"让系统正确"。** 代码大部分已经就位，后面主要是实验和数据。
