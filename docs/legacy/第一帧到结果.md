# 第一帧到结果

## 现在可运行

双击包根目录「启动中控台.cmd」，确认左下为0.4，打开「离线检测」。选择16K合成演示可检查整条电脑处理链。导入实际相机软件导出的P5 Mono8后，选择该文件，设置邻域半径、亮/暗极性和阈值，运行离线检测。点选候选检查源图、校正图与掩膜，再导出完整JSON。

上传文件最多8Mi像素；宽16384时最多512行。大图不能简单分割后把独立区域结果宣称为跨界连续检测。大图/连续流应接已有stream_pipeline与StreamComponents，保留halo与CC前沿，正确的完整帧末尾才finish。当前上传入口是独立图像验证入口。

## 相机到位后的顺序

1. 检查实际供电、Camera Link线及相机输出配置。仅接一根CL1线时，双方要匹配相机真实支持的Base输出及tap/位深；连线数量本身不能证明配置正确。
2. 在「采集控制」手动连接J83串口、唤醒终端、检查板卡、加载原单帧程序。确认Linux、PCIe和接收程序身份，再检查CL1时钟与格式。不要凭旧日志判断这次状态。
3. 首先采单帧。只有完整帧头、尺寸、DMA接收和停止均成功，才采用生成的PGM。失败就保留日志，在当前阶段定位；不要先上连续采集或PL。
4. 成功文件在板上/tmp/sg3000-console，断电会丢。经已验证的文件传输方式复制到电脑，核对板端与电脑的SHA256；尚未实现大图自动串口回传。若配置了SSH网络，可使用scp；当前包不会假定板卡IP、账户或网络已可用。
5. 用「离线检测」导入PGM，先核对尺寸、源图、亮暗响应与坐标，再导出JSON。黑盖测试用于检查暗电平/条纹/传输，不用于证明正常成像或缺陷精度。随后用可见图案检查方向、tap排列、行连续性及固定图样，最后再做暗场玻璃样本与人工标注比较。
6. 单帧通过后再验证连续收流、队列满停止、超时/中断和断线后的恢复。最后接PL驱动、DMA缓存同步和实际硬件地址映射；软件离线成功不能替代这一步。

## 保留的结果合同

- 文件检测为source=uploaded-pgm、provenance=file-native，decision=unknown。输入及输出摘要随结果保存；没有候选也不等于合格。
- bbox=[x0,y0,x1,y1]是源像素全局半开区间，缩略图只用于显示。完整JSON包含全部候选；不把第一页当全帧。
- 文件验证只使用frame_id=0。真实连续接入要保留真实帧号、全局行号、丢行/中断事件；采集块边界不是帧边界。
- SGJSON schema=1仍为连续灰度统计。候选通过frame-candidates-v1 / frame-candidates-export-v1，不混用旧协议。
- 原FPGA/RTL/IP、SD启动文件、板端程序和驱动均保持原基线。改接口前先执行根目录verify_integration.ps1；改HLS还需原模块综合及协同仿真。

这是操作入口与接入约定。真实相机时序、图像DMA、暗场成像与检测精度仍需设备恢复后验证。
