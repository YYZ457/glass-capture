# 操作说明

> v0.2 补充：本页保留基础单帧操作。连续接收、处理接口和新部署方式请读《连续采集与处理接口.md》。核心源码已升级，board 根目录的单帧二进制仍是旧基线。

## 不在实验室时

双击启动中控台，不会向硬件发送任何命令。打开「核心代码」查看主程序及逐行入口；「历史与验证」中是 2026-10-23 的旧记录，绝不作为实时状态。

## 回到实验室后

1. 板子插原 SD 卡并上电，连接 J83 USB 串口。JTAG 可保留；中控台不使用 JTAG。
2. 关闭其他占用控制台端口的串口软件。点击刷新，选择 CP2108 的 Linux 控制台端口。历史为 COM10，当前可能不同。不要选蓝牙端口。
3. 点击连接，再点击唤醒终端。中控台发送回车并等待 root 提示符。若看到登录界面、U-Boot 或其他内容，先断开中控台，用串口工具处理后再连接。
4. 点击检查板卡，读取板型、架构、内核、PCIe ID 与 SD 卡设备。只有 ZCU102、aarch64、5.15.19-xilinx-v2022.1、4c54:3000 匹配才启用后续操作。
5. 点击从 SD 加载接收程序。只读挂载 `/dev/mmcblk0p1` 到 `/mnt/sg3000-console`，校验 `/sg3000-linux-20261023/SHA256SUMS`，拷入 `/tmp/sg3000-board`，卸载 SD，再加载驱动。不会解绑其他驱动，不修改 SD 启动文件。
6. 点击检查采集条件。读取 DDR 与 CL1 时钟；两者满足后才读取 Base/Mono8 配置。早期退出时的配置字段显示为「未确认读取」，不会把初始化的零当作配置。
7. 相机恢复后尝试采集一帧。程序会重新检查条件，等待图像最多 10 秒；结果显示在日志。此操作会启动实际采集和 DMA，仅在你点击时执行。
8. 成功图像在 `/tmp/sg3000-console/frame-时间-随机标识.pgm`。它在板上内存，断电消失。当前中控台不自动传回大图；请在后续联网传输或保存到 SD 后再导入本地查看。不要把网页上的本地图像当作本次采集成功的证据。
9. 结束时可卸载接收驱动并同步文件，再断开串口。卸载不是 Linux 关机；中控台不宣称整个系统已可断电。

## 日志与异常

命令、串口原始输出、错误和阶段结果写入 `runtime/session-*.jsonl`，可从界面导出。网页只保留最近一部分显示，磁盘日志完整。
每条命令都有随机开始/完成标记，避免把命令回显当作执行成功。串口断线、超时、非零退出都不会显示通过。
中断会发送 Ctrl+C 并等待应用退出与清理；不能据此确认硬件 DMA 已停止。未收到完成标记时状态未知，查看日志并重新确认 Linux 提示符，再检查板卡。
重连会清除本次状态；已断开时旧观测标注为断开前记录。板卡输出是观测值，不是永久状态。

## 源码的调用路径

```text
浏览器按钮
  → console/server.py：本机接口
  → console/transport.py：串口执行预定义命令
  → 板上 sg3000-capture main()：解析 preflight / capture
  → sg3000_capture_core.c：信号检查、帧头、分块、拼接
  → ioctl(SG_IOC_DMA_READ)
  → sg3000_rx.c：内核申请的 DMA 内存、描述符、完成检查
  → SG3000 的 PCIe DMA 引擎
```

先看 `core/sg3000_capture.c:120` 的 main；它在 166 行检查、172 行采集、180 行保存。再看 `core/sg3000_capture_core.c` 的 sg_stream_begin、sg_stream_next、sg_stream_end；单帧入口 sg_capture_once 复用这三个阶段。最后看 `core/sg3000_rx.c:102` 的 sg_dma_read。

内核模块没有普通 main：PCI 驱动注册后由内核调用 sg_probe。设备节点为 `/dev/sg3000_rx_0000:01:00.0`。本机网页不是 FPGA 逻辑；采集仍在 ZCU102 ARM/Linux 与 SG3000 上执行。

## 构建与已验证文件

`powershell -ExecutionPolicy Bypass -File build/receiver.ps1` 使用本机 Vitis 2022.1 的 AArch64 GCC11.2 编译静态接收程序，新产物放入 build/output。

驱动需要 Linux 编译环境。`build/module.sh` 要求 KDIR 指向已准备的 linux-xlnx 内核树，固定提交 `b0c1be301e78c320df8c4d93b18393bfd7fd4e9d`；KERNEL_ANALYSIS 指向包含 Image 和 symbols.json 的目录。已有外部材料在 `D:\CodexData\visionkit_zcu102\linux_build_vm` 与 `D:\CodexData\visionkit_zcu102\boot_2022_1\kernel_analysis`，不打包大型工具链。

驱动编译后的实际内核导出符号验证由 verify_module.py 完成。构建成功不表示已经上板验证。这里保留的 board/ 是先前验证过加载的二进制，当前源码已在 v0.2 增加连续接收，旧板上文件没有被自动替换。

## 已知边界

- 基础验证覆盖端口 0、Base、Mono8、无填充、单帧；v0.2 新增连续逻辑，但尚未上板验证。
- 相机维修中。历史 DDRInitialStatus=2，CL1 时钟未锁定；DDR=2 的确切解释待核实。
- 真实图像 DMA 尚未验证；控制访问、驱动加载和模拟数据测试不等于图像传输成功。
- PGM 查看器支持 P5 / maxval=255，至多 3200 万像素；只做本地查看，不修改源文件。
- 本机服务不提供任意 shell 或任意寄存器写入接口，避免把常用操作变成难以追踪的状态修改。深度调试可根据日志与源码另行开展。
- 改动源码后，需要重新编译、验证并明确部署；界面不会偷偷覆盖已验证的程序。
