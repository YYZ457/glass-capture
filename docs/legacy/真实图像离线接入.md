# 真实 PGM 图像的离线检测入口

`console/offline_frames.py` 将用户上传的完整 P5 Mono8 图像送入 `console/process_frame.py` 有界文件处理程序，输出候选 JSONL、校正图和掩膜。它复用未修改的 `PgmStream`、`process_chunks`、`NativeEngine`、`decode_words` 和 `StreamComponents`，数值处理调用与相邻模块原有示例一致：完整条带 halo → 256×64 核心分块 → 全宽核心行 → 跨条带同极性 8 邻接合并。输入源是文件；计算在电脑 DLL 中执行。

该入口不连接相机、SG3000、串口或 FPGA。`source="uploaded-pgm"`、`provenance="file-native"`、`decision="unknown"`、`board_tested=false`、`accuracy_evaluated=false`。真实图像文件成功处理不表示相机采集、板端运行或玻璃缺陷精度已验证。测试中的图像由测试构造，用于核对源像素、分块与文件链路，不作为玻璃精度证据。

## Python 调用合同

```python
from offline_frames import FrameService

service = FrameService(bundle_root)
with open(local_pgm, "rb") as source:
    uploaded = service.register_pgm(source, source_length, "glass.pgm")
started = service.start({"input_id": uploaded["input_id"], "radius": 7,
                         "threshold": 25, "polarity": "both"})
state = service.state()
# 轮询到对应任务 status == "complete" 后：
page = service.results(started["id"], offset=0, limit=100)
png_bytes = service.image(started["id"], kind="source", x=0, y=0,
                          width=256, height=64)
```

`bundle_root` 是同时含 `SG3000Workbench` 和 `linescan_preprocess_v2` 的包根目录。输出固定为 `SG3000Workbench/runtime/frames`；可显式传入相同的 `output_root`，不能通过参数改到任意路径。示例中的 `open` 由本地调用者执行，服务和 HTTP 合同不接受本地输入路径。

| 方法 | 返回与约束 |
|---|---|
| `register_pgm(stream, bounded_length, display_name)` | `{input_id,width,height}`；流中必须提供恰好 `bounded_length` 字节，可碎片读取。只消费当前正文，不读取下一 HTTP 请求。 |
| `start({input_id,radius,threshold,polarity})` | `{id,status:"running"}`，后台启动一个子进程。radius 默认7、整数0..7；threshold 默认25、整数1..255；polarity 默认both，可选both/bright/dark。 |
| `state()` | `{busy,current,runs,inputs}`；current为最近任务或null，runs/inputs按登记时间倒序。inputs含input_id、width、height、display_name、bytes、sha256、created_at、source。 |
| `results(id,offset=0,limit=100)` | `{schema_version:"frame-candidates-v1",run,pagination,components}`；offset为非负安全整数，limit整数1..1000。 |
| `image(id,kind="source",x=0,y=0,width=None,height=None)` | 灰度PNG字节；kind可选source/corrected/mask。只允许已完成并复验的任务。 |
| `export(id)` | 完整UTF-8 JSON字节：`{schema_version:"frame-candidates-export-v1",run,components}`；只执行一次完整产物验证，再顺序读取全部候选，避免前端逐页反复扫描。 |

非法参数或忙碌抛 `ValueError`，合法但不存在的编号抛 `KeyError`，未完成/失败任务抛 `RuntimeError`。布尔、浮点、数字字符串、未知键、输入路径、执行文件路径、校正表路径和输出路径均不能作为处理参数。调用者提供的显示文件名只保留最后一段，不参与路径构造；页面应以文本显示，不能插入HTML。

## 上传、完成与持久化

仅接受 P5、maxval 255、宽1..16384、高1..65536，总像素不超过8Mi（8,388,608）；原始上传正文不超过8Mi+4096字节。头部最多4096字节，允许头部注释；maxval后的单个分隔符（CRLF视为一个）之后立即开始二进制像素，不能跳过像素里的空格、换行或 `#`。完整像素数必须与头部精确一致，缺失和正文内尾随数据都拒绝。

服务先将正文流式写入随机输入编号下的临时文件，严格解析完成后才提交 `source.pgm` 和输入索引；失败上传不进入inputs列表。输入正文保存为独立副本，之后没有修改接口。`input_id` 仅允许 `input-` 加32位小写十六进制；源文件固定为 `runtime/frames/<input_id>/source.pgm`。源文件SHA256写入输入索引和任务索引，启动、完成校验与读取结果时重新核对。原文件名、路径或浏览器传入文本不会影响文件存储位置。

每个任务编号为 `frame-` 加32位小写十六进制。服务将固定处理脚本、可信包根目录、随包DLL、输入编号解析出的固定源文件和固定输出目录传给子进程，不通过shell拼接命令。一次只运行一个任务；子进程上限120秒，超时会终止并回收。候选JSONL上限4MiB，写下一条记录会超限时立即失败，错误提示减小图像或提高阈值；不会截断结果、伪装complete，也不会先生成巨大文件再删。PGM最多8Mi像素加小头部，单个产物小于10MB。参数非法、程序失败、超时、缺失/不完整产物、元数据不匹配、候选非法或摘要不匹配时任务变成failed，不能读取其图像或候选。部分 `.partial` 文件不参与结果发布。

只有原生程序正常结束、原始 `run.json` 标记complete、两幅PGM与完整JSONL校验通过后，服务才发布complete状态。它保存源SHA256、原始输出字摘要及 `run.json`、`corrected.pgm`、`mask.pgm`、`components.jsonl` 各自SHA256；后续读取如发现变化会将该任务标为failed。SHA256用于文件完整性和可追溯性，不是算法精度指标。

重启会重新校验输入和完整历史结果；以前的running任务改为failed，错误说明服务中断。未登记临时文件和没有完整索引的运行目录不会被当作完成结果恢复。状态索引为 `runtime/frames/<id>.json`，日志为 `<run-id>.log`，原生结果位于 `<run-id>/`。旧固定合成入口 `defects-v1` 和旧灰度统计SGJSON协议保持原合同。

## 坐标、分页和图像

机器格式见 `interfaces/frame-candidates-v1.schema.json`。该合同独立于固定16384×135合成演示，帧尺寸来自上传文件。完成任务除来源、时间与参数外包含 `input_id`、`input_sha256`、`display_name`、`width`、`height`、`component_count`、`output_words_sha256`、`output_sha256`、`images`、原生耗时、条带数和输入缓存峰值。options中保留input_id和三项算法参数。

候选最小面积2，bbox为全局源像素半开区间 `[x0,y0,x1,y1]`，不使用缩略图坐标。`area` 是命中像素数，`peak` 是正的绝对DN幅度，`signed_peak` 对亮为正、暗为负；上传文件使用frame_id=0。候选 `c000001` 等编号来自完整JSONL固定输出顺序，分页不会重排或重新编号。

成功任务的JSONL保存全部候选，不截断。`pagination` 含offset、limit、total、returned、has_more；超出尾部返回空页。API调用者如自行逐页导出，必须累积到has_more=false，不能将第一页当作完整帧。中控台完整导出使用 `export(id)`，紧凑JSON总上限8MiB，超限则明确报错，绝不返回部分导出。4MiB原始JSONL限制为新增候选ID和来源字段后的完整导出预留空间。

不传width/height时生成全视野概览，使用统一步长 `max(1,ceil(width/2048),ceil(height/1024))`，最大2048×1024。`images.source/corrected/mask` 均记录source_width、source_height、preview_width、preview_height、downsample_step。source与corrected按步长采样，mask对每个方块最大池化，尾部补零，小命中不会因抽样消失。池化后的亮点不表示实际缺陷面积。绘制候选框应按downsample_step将源坐标映射到概览。

传入裁剪尺寸时宽1..1024、高1..512，x/y非负整数，范围须完全位于源图内；返回原始源像素，无缩放。width/height必须同时传；只有x/y的请求拒绝。kind=source可以检查原始上传像素，corrected检查校正输出，mask检查阈值命中。

## 从相机接入前仍需完成

此入口可先处理相机软件导出的完整P5文件，明确输出候选而不做良品/不良品判定。连续相机流仍需实现SDK回调/DMA缓冲所有权、格式/步长、帧号与全局行号、溢出/丢行/中止事件。采集块不是帧边界：跨块保持halo与CC前沿，实际完整帧才finish，丢行或中断帧不得作为complete结果。不要将本入口的 `file-native` 来源用于硬件流；硬件接入需要独立的来源与完整性合同。

## 离线验证

在包根目录执行 `python -m pytest SG3000Workbench/tests/test_offline_frames.py -q`，需要NumPy、pytest、jsonschema与Windows随包DLL。受限环境可加 `--basetemp <工作区内新目录>`。测试执行实际上传图像→原生DLL→JSONL/PGM/PNG链路，覆盖16K的x256/y64跨块候选和输出字摘要、动态小图与高图、分页和完整导出、源像素裁剪、掩膜池化、上传碎片/二进制空白、严格格式边界、参数/编号、并发拒绝、真实子进程超时及恢复、真实密集候选触发文件上限、损坏文件和重启。不访问硬件，也没有真实玻璃样本精度测试。
