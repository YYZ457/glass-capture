# 离线 16K 缺陷候选接口

中控台 `console/defects.py` 使用同目录模块包里的 `linescan_preprocess_v2/examples/run_linescan.py`，通过其 `NativeEngine` 调用随包 DLL。计算代码与导出 FPGA IP 的 C++ 相同。本入口不连接相机、SG3000、串口或 FPGA，不构造 DMA 地址，不修改 FPGA 模块源码。

当前输入固定为示例生成的 **16384×135 Mono8 合成图像**。输出是局部背景阈值的候选，`decision` 始终为 `unknown`，不是产品良品/不良品分类；`board_tested=false`、`accuracy_evaluated=false`。亮/暗边缘附近的反向候选是方框背景响应的实际输出，不能据此评估真实玻璃准确率。

## Python 入口与 HTTP 对应

构造：`DefectService(bundle_root, output_root)`。`bundle_root` 是同时含 `linescan_preprocess_v2`、`sample_output_16k`、`SG3000Workbench` 的模块包根目录；输出固定为其 `SG3000Workbench/runtime/defects`。

| Python | HTTP | 返回 |
|---|---|---|
| `start(options=None)` | `POST /api/defects/start`，JSON 为参数对象 | `{id,status:"running"}`，立即返回 |
| `replay()` | `POST /api/defects/replay`，JSON `{}` | `{id:"replay-16k",status:"complete"}` |
| `state()` | `GET /api/defects/state` | `{busy,current,runs}` |
| `results(id,offset=0,limit=100)` | `GET /api/defects/results?id=...&offset=0&limit=100` | 一页候选和完整运行元数据 |
| `image(id,kind="corrected",x=0,y=0,width=None,height=None)` | `GET /api/defects/image?id=...&kind=mask` | 灰度 PNG 字节 |

POST 的本机来源与会话令牌由中控台 HTTP 层统一检查。错误由 HTTP 层转为 JSON `error`；Python 参数非法/忙碌抛 `ValueError`，不存在的编号抛 `KeyError`，运行未成功完成抛 `RuntimeError`。

`start` 只允许 `radius` 整数 0..7（默认 7）、`threshold` 整数 1..255（默认 25）、`polarity` 字符串 `both|bright|dark`（默认 `both`）。布尔、浮点、数字字符串与未知键均拒绝，不接受任意输入路径、命令、库路径或输出路径。默认演示实际输出 **7 个候选**；r0 没有背景差值，候选数为 0。

`state.current` 是最近任务的运行元数据或 `null`；`runs` 按创建时间倒序。异步运行期间 `busy=true`，`status="running"`。只有子进程正常退出、`run.json` 标记完整、全部图像和完整 JSONL 验证通过才成为 `complete`。进程退出失败、60 秒超时、输出缺失、参数/尺寸不匹配、非法候选均成为 `failed`，错误保留在 `error`，可继续启动新任务。超时由 `subprocess.run` 终止并回收子进程。重启后重新校验历史完整结果；未完成的旧任务变成失败，不冒充仍在运行。

`replay` 只读取 `sample_output_16k` 的历史结果，来源是 `recorded-replay`，不重新计算、不写入样例目录。新原生任务来源是 `synthetic-native`。忙碌时拒绝新的计算和回放，已完成历史结果仍可读取。运行编号只允许 `run-` 后跟 32 位小写十六进制或固定 `replay-16k`，文件名固定，没有文件路径读取接口。

## JSON 页与坐标

机器定义见 `interfaces/defects-v1.schema.json`。`results` 返回：

```json
{
  "schema_version": "defects-v1",
  "run": {
    "id": "replay-16k", "status": "complete",
    "width": 16384, "height": 135, "component_count": 7,
    "radius": 7, "threshold": 25, "polarity": "both",
    "provenance": "recorded-replay", "decision": "unknown", "board_tested": false
  },
  "pagination": {"offset": 0, "limit": 100, "total": 7, "returned": 7, "has_more": false},
  "components": [
    {"id":"c000001","bbox":[16380,0,16384,3],"polarity":"bright","area":12,"peak":93,"signed_peak":93,"frame_id":0,"decision":"unknown"}
  ]
}
```

上述示意省略其余候选及 `run` 中的时间、参数副本、图像尺寸和原生证据字段；实际响应遵循完整 schema。`created_at`、`finished_at` 是本机 Unix 秒。`native_wall_seconds`、`stripes`、`retained_input_cache_peak_bytes`、`output_words_sha256` 来自原始运行元数据；回放中它们是记录值，不是本次 UI 查询耗时。默认原生输出字摘要为 `35ebca3127ab78ebdfe700368ec338d8952399e1999abca31450aa9118fe9a5e`。

候选以同极性 8 邻接合并，最小面积 2；bbox 为全局源像素半开区间 `[x0,y0,x1,y1]`，宽高分别为 `x1-x0`、`y1-y0`。`area` 是命中像素数，不是 bbox 面积。`peak` 为正的绝对 DN 幅度（1..255），`signed_peak` 对亮候选为正、暗候选为负；不表示整个 bbox 的统一灰度。`frame_id` 为 uint64，超出 JavaScript 安全整数 2^53-1 后用十进制字符串返回。候选 ID 来自原始 JSONL 的固定输出顺序，分页不会重新排序或编号。

`offset` 为非负安全整数，`limit=1..1000`；超出尾部返回空数组。磁盘 `components.jsonl` 保留全部候选，分页只限制单次响应。导出全部结果时从 offset 0 开始逐页取，依 `has_more` 继续；不能把第一页冒充全部。schema 描述字段类型和边界；服务额外验证 bbox 有序且在图内、面积不大于 bbox 面积、peak 达到阈值、候选极性符合请求、JSONL 数量与元数据一致等关系约束。

## 概览与局部原像素图

`kind=corrected|mask`。不传宽高时返回完整视野概览，最大宽度 2048。固定演示按 x/y 相同的 8 倍步长缩小到 **2048×17**；`run.images.corrected` 与 `run.images.mask` 都含 `source_width/source_height=16384/135`、`preview_width/preview_height=2048/17`。校正图按步长采样；掩膜按 8×8 最大池化，边缘补零后池化，保留单像素小缺陷。池化后的亮点不是原始缺陷面积。绘制 bbox 应按源坐标除以 8，而不是将最后一行的边缘补齐误认为原图新增像素。

裁剪必须同时传 `x,y,width,height`，坐标和尺寸均为整数，宽 1..1024、高 1..512，范围须完全在真实源图内。裁剪不缩放，PNG 每个像素对应一个源像素；适合查看候选附近实际灰度与掩膜。仅传 x/y 或只传一个尺寸拒绝。图像头最多读取 4096 字节，严格检查 Mono8 P5、尺寸、完整像素数和尾随数据；不接受任意文件格式或 URL。

## 后续 Gemini 接入位置

1. UI 保持使用 `console/web/defects.js` 的全局坐标与半开 bbox；不要把降采样预览上的坐标当输入坐标。全宽图只画当前候选页，切页后更新覆盖框。
2. 当前 HTTP 结果 `defects-v1` 专门标识固定离线演示，schema 固定尺寸和来源。接真实图像时新增版本化 provider/结果合同，明确 source、帧尺寸、全局起始行、帧/会话终止、连续性错误；不要放宽旧字段后把硬件结果标成 synthetic-native。
3. 板端采集接口仍在 `core/sg_processing.h`，借用像素仅在同步调用期间有效。新后端内部需要保存跨采集块的 halo 和 CC 前沿；实际帧完成才 finish。正式中断或丢行则终止该帧并标为 incomplete，不能将其当完整结果。
4. PL 控制复用相邻模块 `python/mmio_runtime.py` 的生命周期，C++ 平台实现遵循同一合同：设备 DMA 地址、sync_for_device、启动、done/status、sync_for_cpu、超时隔离、reset/drain。当前 `sg_pl_uapi.h` 是旧统计接口，不能不改ABI就交给新 preprocess_tile IP。
5. `SGJSON schema=1` 仍由原 transport 解析灰度统计。新候选事件需要升级串口协议、解析器和 schema，并增加完整帧/序号/停止异常测试；本次没有将新候选冒充旧统计结果。

浏览器「导出候选 JSON」逐页收齐后生成 `schema_version=defects-export-v1`，结构为 `{schema_version,run,components}`，不带分页字段，全部候选不截断。机器合同见 `interfaces/defects-export-v1.schema.json`。它复用分页合同的 run/component 定义；浏览器下载路径由浏览器决定，原始结果始终留在随包 runtime/defects。

## 运行产物与验证

新任务文件位于 `runtime/defects/<run-id>/`：`run.json`、`corrected.pgm`、`mask.pgm`、`components.jsonl`。原始 `.partial` 只在原生运行期间出现。服务在输出根目录记录 `<run-id>.json` 状态与 `<run-id>.log` stdout/stderr 日志。当前两幅源图各约 2.2MB；入口固定演示，图像解析上限 8Mi 像素。原始 JSONL 不截断，单条记录上限 65536 字节。

使用随包 Python 环境运行 `python -m pytest SG3000Workbench/tests/test_defects.py -q`。测试包含真实 DLL 默认 7 候选与 r0 空结果、摘要核对、进程失败/超时、并发拒绝、重启、样例只读回放、逐页稳定 ID、uint64、非法参数/元数据、PNG CRC/源像素裁剪、掩膜池化和 schema 一致性。测试使用临时复制的模块和样例，不访问硬件。
