# D003 · 不再给二进制打补丁

**状态**：生效（2026-11-06）

**事实**：板上 `sg3000-capture` 是旧源码编译的，要求 DDR 状态 = 0；实际硬件返回 2（已校准，正常）。
中控台每次往文件偏移 5736 写 `1f 20 03 d5`（ARM64 NOP），把 `cbnz w0` 这条检查删掉才能采图。
副作用：DDR 状态无论是多少（包括真正出错的值）都会放行。

源码早已改成"0 或 2 都算正常"（legacy `sg3000_capture_core.c` 第 95-97 行），只是没重新编译上板。

**决定**：

1. 用源码重新交叉编译后上板，去掉补丁。
2. 之后任何"能跑但不知为什么"的修改，都写进 `docs/decisions/`，不允许出现在二进制里。
